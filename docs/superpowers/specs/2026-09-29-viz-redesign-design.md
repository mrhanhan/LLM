# viz 3D 可视化重构设计文档

- 日期：2026-09-29
- 状态：待评审
- 类型：架构级（viz 子系统完全重构）
- 参考：bbycroft.net/llm 的"层叠架构 + 可展开权重矩阵"范式

## 1. 背景与目标

现有 `viz/`（`docs/07-visualization.md`）有三个视图：分层网络图（发光球 + 细线）、
神经元点云、12 个真实模型架构浏览器。用户反馈**可视化效果差**，想要的是
**类似模型架构图**：像 bbycroft.net/llm 一样，从上到下或纵深堆叠出每一层，
**每一层可展开**，层内以**权重矩阵视图**呈现——矩阵由许多方块组成，
方块上带**数值、颜色、连接方式**。

本次对 `viz/` 做**完全重构**，围绕该范式重写前端渲染与后端数据层。

### 目标

1. **架构感**：竖直"书架"逐层堆叠，点击某层可展开/收起，展开动画过渡。
2. **权重矩阵视图**：每个矩阵按"方块"呈现；颜色 = 数值（发散色阶），
   悬停/点击可见具体数值与行列索引，方块之间/层之间可见连接。
3. **多数据源并存**：
   - **A 真实模型检视**：本地 `out/gpt/latest.pt`（d_model=768 / 12 层，约 1.9 亿参数）
     的静态权重可视化 + 逐 token 推理流动。
   - **B 实时训练**：现有字符级小模型（d_model=64 / 4 层），实时权重变化与 loss 曲线。
   - **C 架构浏览器**：12 个真实大模型，**仅结构 / 公式 / 源码**（无权重）。
4. **保留**四项既有能力：实时训练、实时推理 + 注意力、神经元点云、架构浏览器。
5. 文档同步：重写 `docs/07-visualization.md`。

### 非目标（YAGNI）

- **不下载**外部 HF 权重；只使用本地 checkpoint。
- 不为万亿参数模型（Kimi K3 等，无公开权重）绘制权重矩阵。
- 不为真实大矩阵做"每元素一个 3D mesh"的全量渲染（改为纹理热力图 + 分块下钻）。
- 不做多用户/远程部署、不做移动端适配。

## 2. 最终选型（可视化原型决策记录）

| 维度 | 决策 | 来源 |
|---|---|---|
| 整体布局 | **C1+C2**：竖直书架 12 层全览；点击某层高亮放大、其余降透明度 | 用户选 C1+C2 |
| 层内排列 | **M1** 单排流水线 `n1 → q k v o → n2 → w1 w2 w3`，叠加 **M2** 分块聚合 + 下钻 | 用户选 M1 |
| 连接方式 | **L1** 常态结构连线为上；推理时叠加 **L3** 数据流带；**L2** 神经元连线仅下钻小矩阵时开启 | 用户选"按推荐" |
| 方块语义 | 小矩阵（面积 ≤ 阈值）用**真 3D 立方块（一方块=一权重）**；大矩阵用**热力图纹理平面**（格=权重，按块聚合，可下钻） | 用户选"每方块=一权重" + "热力图纹理平面"降级 |
| 激发动画 | 推理时**自动逐 token 播放**，可暂停/单步/回放 | 用户选自动播放 |
| 规模与来源 | 主打真实模型（本地 checkpoint）；实时训练用小模型，二者并存 | 用户选"本地 checkpoint"+"两套数据源并存" |
| 超大模型 | 架构浏览器仅结构/公式，不接权重 | 用户选"仅结构视图" |

**为什么"每方块=一权重"必须降级**：真实矩阵 768×768 = 59 万方块，
`tok_emb` 151666×768 ≈ 1.16 亿方块，全量离散方块不可行。故：
小矩阵 → 立方块；大矩阵 → 服务端生成发散色阶热力图纹理贴到平面上，
默认按 N×N 分块聚合，双击/放大再下钻到元素级。

## 3. 信息架构 / 界面外壳

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏  brand │ 模式[检视·训练·架构] │ 模型/checkpoint │ 状态        │
├───────────┬──────────────────────────────────┬───────────────┤
│ 左栏       │                                  │ 右抽屉(2D)     │
│ 层/模块树  │     3D 书架主视图 (WebGL)         │ 选中矩阵热力图  │
│ + 控制     │  层托盘·矩阵板·连线·流带          │ 图例/统计/公式/代码│
│ (可折叠)   │                                  │ 神经元点云(切换) │
├───────────┴──────────────────────────────────┴───────────────┤
│ 底栏  推理播放器(▶/⏸/单步) │ 训练 loss 曲线 │ 提示/悬停数值      │
└──────────────────────────────────────────────────────────────┘
```

- **层托盘**：折叠态 = 薄板 + 层标签；展开态 = 7 个矩阵板按 M1 排布。
  **同一时刻只展开一层**（C1+C2），其余保持折叠 → 几何量有界。
- **拾取**：射线命中矩阵板 → 由 UV 换算格/块索引 → 拉取数值显示于底栏。
- **右抽屉**：点击矩阵板打开，2D 大热力图（含坐标轴、行/列范数条、
  块↔元素切换、色阶图例、KaTeX 公式与源码）。可切到该矩阵的神经元点云。

> 模式只有三个：**检视**（真实 checkpoint）/ **训练**（小模型）/ **架构浏览器**。
> "推理播放"不是独立模式，而是检视与训练模式下均可触发的动作
> （检视用真实模型、训练用小模型）。

## 4. 后端设计（FastAPI + WebSocket，重构）

### 4.1 模块划分

- `viz/graph.py`（新，取代 `topology.py` 的节点构建）：为真实/小模型生成**统一模型图**：
  - `layers[]`（index/label）→ `modules[]`（norm/attn/mlp）→ `matrices[]`
    （`name/label/role/shape[out,in]/layer/module/tiles`）
  - `connections[]`：`{id, src, dst, kind, weight_from}`，kind ∈ `spine|inner|flow`
- `viz/weights.py`（新）：真实 checkpoint 数据层
  - `load_checkpoint(path, config)`：加载模型（只读、懒加载，供静态检视）
  - `matrix_grid(name, tiles)` → 分块聚合二维网格（每块 = 均值/范数）
  - `matrix_png(name, tiles)` → **发散色阶 PNG**（服务端统一色阶，客户端当纹理）
  - `matrix_cell(name,i,j)` / `matrix_patch(name,r,c,h,w)` → 元素级数值
  - `stats(name)` / `global_stats()` → vmin/vmax/mean/std（全局与逐矩阵）
- `viz/runtime.py`（扩展）：保留小模型实时训练与逐 token 推理；
  新增真实模型推理（forward hook 取各模块激活，供 L3 流动与注意力）。
- `viz/arch.py` + `viz/architectures/*.json`：保留，仅架构浏览器结构/公式使用。
- `viz/server.py`：重写路由与广播。

### 4.2 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | index.html |
| GET | `/api/model?source=ckpt\|live` | 模型图（layers/modules/matrices/connections）+ 全局色阶 |
| GET | `/api/matrix/{name}/png?tiles=N` | 发散色阶 PNG 纹理 |
| GET | `/api/matrix/{name}/stats?tiles=N` | 该矩阵统计与网格尺寸 |
| GET | `/api/matrix/{name}/cell?i=&j=` | 单元素数值 |
| GET | `/api/matrix/{name}/patch?r=&c=&h=&w=` | 元素子块（下钻） |
| GET | `/api/neurons?matrix=&n=&top=` | PCA 神经元点云（沿用） |
| GET | `/api/arch/list` · `/api/arch/{id}` | 架构浏览器（沿用） |
| GET | `/api/state` | 训练/推理状态 |
| POST | `/api/train/start\|stop` · `/api/infer` | 触发训练/推理 |
| WS | `/ws` | 实时推送 |

### 4.3 WebSocket 协议

| type | 内容 |
|---|---|
| `init` | `{source, mode, layers, matrices, connections, color_scale}` |
| `tick` | `{step, loss, lr, values:{matrixName:{norm,mean,max,delta}}}` |
| `token` | `{token, text, values:{matrixName:{act}}, attn:[...], flow:{...}}` |
| `status` | `{training: bool}` |

颜色映射：正=暖红、负=冷蓝、近零=暗；图例可选「全局归一化 / 本矩阵归一化」。

## 5. 前端设计（Three.js，重写 `viz/static/`）

- 模块化文件：
  - `main.js` 场景/渲染循环/模式切换
  - `shelf.js` 书架布局与展开/收起动画（C1+C2）
  - `matrix.js` 矩阵板：纹理热力图、InstancedMesh 立方块、拾取与悬停
  - `links.js` L1 结构连线 / L2 神经元连线 / L3 数据流带
  - `panel.js` 右抽屉 2D 热力图 + KaTeX 公式/代码 + 行列统计
  - `cloud.js` 神经元点云（PCA，沿用后端 `/api/neurons`）
  - `colors.js` 发散色阶/图例/归一化
  - `api.js` HTTP/WS 封装
  - `arch.js` 架构浏览器视图
- 颜色：发散色阶，正红负蓝；权重态与激活态各一套映射与图例。
- 交互：旋转/缩放/平移；点层展开（互斥）；点板开抽屉；悬停取数值。
- 推理：自动逐 token 播放，底栏暂停/单步/回放；L3 流带随 token 点亮推进，
  注意力热力图同步；训练：实时刷新颜色/线粗 + loss 曲线。

## 6. 性能策略

- **纹理平面**（DataTexture/CanvasTexture）承载大矩阵；`tiles` 默认 64、上限 256。
- **InstancedMesh** 承载小矩阵立方块；面积阈值可配（默认 64×64）。
- 连线 **top-k** 截断；LOD 控制；只展开单层。
- 真实模型 12×7 = 84 张 ≤256² 纹理，显存/带宽可控。
- **懒加载**：checkpoint 仅在"检视"模式加载；默认进入轻量模式。
- 小矩阵"立方块"判定：矩阵元素数 **≤ 4096（约 64×64）** 时用 InstancedMesh 立方块，
  否则用纹理平面；阈值可配置。

## 8. 测试与验收

**单元测试（`tests/test_viz.py` 更新）**
- 模型图：小模型与真实 checkpoint 均能生成 layers/modules/matrices/connections，形状正确。
- 矩阵 PNG：尺寸与 `tiles` 一致；`matrix_cell(i,j)` 与 torch 权重值一致。
- 分块聚合正确；`stats` 与 torch 计算一致。
- 架构列表/详情可用；`server.py --check` 冒烟通过。

**手动冒烟**
1. 两套数据源（检视 / 训练）可切换且互不干扰。
2. 点层展开/收起有动画；同一时刻仅一层展开。
3. 悬停板显示数值与行列；点板右抽屉显示 2D 热力图、公式、源码。
4. 大矩阵默认分块、双击下钻到元素；小矩阵显示立方块。
5. 推理自动播放：L3 流带 + 注意力热力图同步；可暂停/单步/回放。
6. 训练：loss 下降、颜色/线粗实时刷新。
7. 神经元点云与架构浏览器仍可用。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 2.2GB checkpoint 加载慢/占内存 | 仅检视模式懒加载；只读；可切回轻量小模型 |
| 大矩阵纹理/方块性能 | tile 聚合 + 尺寸上限 + InstancedMesh + 只展开单层 |
| 真实模型 CPU 推理慢 | 限制生成 token 数与层数；预取；可后台线程 |
| 前端完全重写工作量大 | 模块化拆分 + 里程碑递进 + 复用 vendor |
| 色阶全局/局部不一致导致误读 | 默认全局归一化 + 图例明确标注 + 可切换 |

## 11. 决策记录（原型问答）

1. 范围：**完全重构 viz**。
2. 渲染：**3D 结构 + 2D 展开面板混合**。
3. 矩阵粒度：**每方块 = 一个权重元素**（小矩阵）；大矩阵降级为**热力图纹理平面 + 分块**。
4. 信息重点：颜色表示数值、悬停显示数值、层间/矩阵间连接、逐 token 激活流动（全选）。
5. 保留能力：实时训练、实时推理 + 注意力、神经元点云、架构浏览器（全选）。
6. 数据规模：**只真实模型**（本地 checkpoint）为主，**实时训练用小模型**，二者并存。
7. 超大模型：**仅结构视图**，不接权重。
8. 布局/层内/连接：见第 2 节选型表（C1+C2 / M1+M2 / L1+L3+L2）。
